# Explicit Small K1 windowed device water

`maple_syrup.windowed_shared_bed_device` is an opt-in adapter for the existing
Native windowed water demand and B2b wet commit. It calls the original SYRUP
`complete_event` once with one real `CudaHydraulics(mode='auto', max_log=256)`.
There is no new water, sediment, avalanche, routing, settlement or dry-reset law.
The existing CPU and default lanes retain their original bodies behind two
removable loaded-module guard/dispatch prefixes.

The initial qualification profile is the labelled synthetic 4x4 Small K1 bed:
V6/W3, Native G4/J320, the existing reduced-test calibration with rejection
outside its envelope, original enabled native avalanche, constant-depth commits,
and the external MASY `fixture_dense_production` all-edge-open water inputs.
The independent Dense CuPy oracle receives the complete same initial physical
bed and water inputs. Rain remains 60 seconds at 72 mm/h, recession guard 180
seconds, reports every 10 seconds, max dt 1 second, 10000 accepted steps and 10
retries. Existing upwind/array transport, 64 substeps, step publication, no
exchange history and real terminal deposition/completion remain unchanged.
A native limit/error remains incomplete. No journal or deep version advance is
forced; an unchanged original handle is legal after an empty publication.

## Lifetimes and authority

The module owns one synchronous process/thread/context-bound operation. The
already-loaded CPU guard checks the device guard before its original body;
device entry checks the genuine CPU guard before constructing an owner.
Foreign/default/CPU calls from any thread and same-context calls from another
thread refuse while the device owner is active. The device guard is pure and
idempotent. The original seven-field shared state, reconciliation baseline,
solver clocks, retained routing source and Native availability remain intact.

Native CUDA hydraulics has no close API. The finally block closes only this
adapter's authority and clears its exact owner. It does not mutate Native
contexts, free a pool, reset an allocator or claim asynchronous cleanup.
Current/prospective/error/traceback CUDA holders and all immutable old/orphan
storage versions remain charged. Original worker cleanup owns the process.

B2b receives a genuine pending HOST journal where present. It composes the real
native avalanche callback, native constant-depth water callback, full native
conservation/partition validation and one publication. The adapter checks the
new identical-content depth copy, unchanged mobile object and zero
clamp/displaced accounting before returning through the unchanged SYRUP routing
logic. A separately reached step publication has its own pre-write admission.
No complete volume is materialized by the adapter; tiny full-column readback is
confined to the independent test oracle.

## Qualification boundary

The Source author executed no Native, provider, model, test or GPU operation.
Root reports standalone StageA wet device commit and StageB direct/paired
Native exchanges accepted under their original scopes. Those are prerequisites,
not full Small K1 hydraulic-event qualification. The new metadata controls and
complete event oracle are authored and unexecuted here. Root must freshly join
actual Source/runtime/compiled/provider/cold/origin/environment/physical UUID,
allocation/grant and resource evidence before running them.

No CPU/GPU carried-chain, K6, larger domain, production calibration, checkpoint,
GPU restart or alternating MASY integration is claimed. StageD additionally
requires a separately qualified Native completed-device record scale receiver;
the existing CPU receiver rejects `_DeviceRecordPlan`. This adapter does not
add a fallback, reconstruct a Dense evolving bed or change numerical tolerances.
