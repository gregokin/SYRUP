## Implementation and caller compatibility

The only change to an existing production function is the exact-source
allowlist in `sediment_bed.check_deep_storage_source`, plus the corresponding
recognizer binding. The new merged digest joins the historical typed-journal
reference. Unknown sources still fail; genuine Dense/Windowed class bindings,
checkpoint source pairs, storage encodings, pending-journal and publication
guards remain enforced. Both checkpoint codecs and all physics are unchanged.

The new `maple_syrup.storage_admission` module exposes **explicit caller checks**
`admit_public` and `admit_paired`. No existing event, CLI or default invokes
these automatically. Immediately before the matching exchange, a caller must
pass the same actual bed/context/options, explicit host reserves and, for
CuPy, device reserves. The helper reuses native `windowed_transaction_bytes`
and `admit_windowed_transaction`, including paired allocating fallback. It
derives geometry, packet terms, stored ledger-process count, pending records,
journal cap, chunk/overlay sizes and cache bounds from the actual state.

The public path derives optional features from the actual demand. The paired
caller must declare the union of pickup and future deposit features; the
future callback is not executed or inspected during admission. The helper
refuses a nondefault gather count because existing SYRUP exchanges actually
use native 256-column gathering. There is no silent planning/execution mismatch.
Invalid reserves and ignored device queries on CPU are refused before querying;
the exact source is checked before importing the optional native planner.

CuPy's default effective-free query uses driver free bytes plus reusable pool
bytes, bounded by the remaining configured pool allowance. It checks the
current device against the bed and does not change devices or pool limits.
CPU admission never imports or queries a GPU. A decision is not a reservation
or a whole-process memory bound. Callers must reserve their own transport and
face-flux scratch, publication/commit buffers, JIT/library workspaces and
allocator/Python overhead. The tiny validation driver's configured reserves
are not universal production budgets. Existing storm drivers do not acquire
automatic memory protection through this dependency update.

Native `process_totals_kg` retains canonical seven-process indexing even when
the compact directional ledger stores fewer process slots. No ledger remapping
or transport-physics correction was needed. Native `surface_creep` is retained.

Existing test changes admit the additional exact qualified digest, check the
genuine optional Dense surface-cache capability, and reconcile old GPU test
fixtures with the already-required net-elevation routing rule. Positive routing
fixtures perform actual native pickup/transfer/deposit to cross the unchanged
0.00075 m threshold. Accounting commits below it do not refresh hydraulics.
No test sets a synthetic reroute flag or lowers a physical threshold.
