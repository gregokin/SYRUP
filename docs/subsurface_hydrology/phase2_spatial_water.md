## One body, two readers (the factoring)

`subsurface.reference_step` was split without any arithmetic change:

* `_reference_step_body(params, active, water_in, added, pet, dt, share=None, recharge=None)` is the former body. Its header no longer reads `column.layers`; it reads indexable attributes of `params` and uses them exactly as before (`sat_m[layer]`, `cap_tol[layer]`, `fc_m[layer]`, `res_m[k]`, `dz[k]`, `pair_inv[k]`, `cond_down[k]`, `cond_up[k]`, plus `res_theta0`, `stress`, `factor`, `directional`, `closed_bottom`, `gravity_drainage`). The stage order, helper constants (`NO_FLAG`, `ROW_COUNT`, `NUMPY_SCRATCH_DOUBLES_PER_CELL`, ...), flags 0-17, closure bound, pulse rule and defaults are untouched.
* `reference_step` / `reference_runner` keep their public signatures and the typed `_check_column` guard; they call the body through `_CommonStepParams(column)`, which exposes the very cached `(L,)` arrays/scalars the body always read (no copy, no recomputation), so the common path performs identical IEEE operations.
* The spatial wrapper (`spatial_soil_layers._SpatialStepParams`, a PRIVATE typed reader honestly named: it is not a `SoilLayers`/`SoilColumn` and claims no legacy ownership) exposes lazy rows over the prepared retained RAW maps.

Source movement vs mathematical change (`s2_a2_subsurface_source_movement.patch` in the task directory): in `subsurface.py` only the `_CommonStepParams` class and the body header lines (`lay = column.layers ...` -> `params.*`) moved, one line `lay.gravity_drainage` -> `params.gravity_drainage`, and the new function boundary. **Mathematical changes: none.** A test compares the executable body text after the header with the pre-A2 text byte for byte, and 32 parametrized scenario groups (L x mode x bottom x gravity; each over four state kinds, five dt values, shares and pulses) compare every `StepArrays` field of the new common path with the pre-A2 source bit for bit (both modes, both bottoms, gravity on/off, shares, pulse, masks, invalid values, dt boundaries).

### Lazy rows (no permanent derived maps)
Per layer `k` the reader derives, from the retained raw maps and with the same IEEE order as `soil_layers`:
`res_m[k] = theta_res[k] * dz[k]`, `fc_m[k] = theta_fc[k] * dz[k]`, `sat_m[k] = theta_sat[k] * dz[k]`, `cap_tol[k] = coef * (theta_sat[k] * dz[k])` with `coef = volume_roundoff_bound_m3(LAYER_OPERATION_TERMS, 1.0)`; `dz[k]`, `pair_inv[k]`, `cond_down[k]`, `cond_up[k]` are direct rows; `res_theta0` is row 0 of `theta_residual`. A row is a float64 scalar for a SCALAR/SHARED layout and an `(N,)` array (a view for retained rows, a fresh array for derived products) for a CELL layout; nothing is cached and no `(L, N)` depth/tolerance/edge map exists. The residual `theta_residual` is only the withdrawal floor in the evaporation stage (`avail0 = w0 - res_m[0]`); zero water is allowed and no residual water is ever added.

## API (module `maple_syrup.spatial_soil_layers`; backend "numpy" only)

```python
spatial_column_state(column, water_m, t_s=0.0, *, memory_budget_bytes, reserve_bytes=0, available_bytes_fn=None) -> SpatialSoilState
spatial_uniform_state(column, theta_by_layer, t_s=0.0, *, memory_budget_bytes, reserve_bytes=0, available_bytes_fn=None) -> SpatialSoilState   # water[k, c] = theta[k] * dz[k, c]; theta_by_layer: real scalar | 0-d/1-D numpy.ndarray of L reals | list/tuple of L reals
spatial_moisture(column, state, *, memory_budget_bytes, reserve_bytes=0, available_bytes_fn=None) -> ndarray (L, N)                            # water / dz
spatial_storage_m3(column, state, *, memory_budget_bytes, reserve_bytes=0, available_bytes_fn=None) -> float                                   # active cells only; SpatialLayerError if the volume is not finite
spatial_step(column, state, dt_s, *, added_water_m, potential_evaporation_m_s, evaporation_share=None, memory_budget_bytes, reserve_bytes=0, available_bytes_fn=None) -> SpatialStep
spatial_step_with_recharge(column, state, dt_s, *, recharge_depth_m, potential_evaporation_m_s, evaporation_share=None, memory_budget_bytes, reserve_bytes=0, available_bytes_fn=None) -> SpatialStep
estimate_spatial_operation_memory(operation, n_layers, n_cells, *, with_evaporation_share=False, reserve_bytes=0) -> SpatialOperationMemory   # operation in state|uniform_state|moisture|storage|step|step_with_recharge
SpatialSoilState(water_m (L, N) float64 read-only, t_s, column_sha256, n_layers, n_cells, component_tag='spatial_numpy_reference_only')  .summary()
SpatialStep(state, dt_s, surface_return_m (N,), drainage_m (N,), evaporation_m (N,), evaporation_unmet_m (N,), percolation_m (L-1, N), diffusion_m (L-1, N) [positive downward], budget: subsurface.StepBudget)
```

Units: m of water per layer, s, m/s, volumes in m3 over active cells (area from the prepared column). `spatial_step` follows `subsurface.step` exactly: addition with saturation return -> field-capacity gravity cascade (open/closed bottom, capacity-limited redistribution, gravity switch) -> layer-0 evaporation (historical law or the post-cap share law) -> sequential pair diffusion in the column's mode (constant D or donor-depth `d K h`) -> output checks and global closure; inactive cells keep their water bit for bit and carry zero fluxes. `spatial_step_with_recharge` is the Phase 1.5 pulse step (one finite non-negative host depth, top layer of every active cell, no saturation return, one gravity cascade, fit test flag 17 -> `SubsurfaceFitFailure`, `dt > 0` and `t + dt > t`). The clock advances by exactly `dt_s`; `dt_s = 0` is the accepted zero-time case (it admits no added water, flag 9). Errors reuse `subsurface`'s: `SubsurfaceError` (time/mode), `SubsurfaceStepError` (staged value flags, closure), `SubsurfaceFitFailure`; metadata errors are `SpatialLayerError`, memory `SpatialLayerMemoryError`, a numba/cuda-prepared owner `SpatialLayerBackendUnavailableError` (refused before any copy; no fallback).

### Helper contracts (correction01)
* **`spatial_uniform_state` input handling.** The metadata of `theta_by_layer` is checked BEFORE anything is converted (a real scalar, a 0-d/1-D `numpy.ndarray` of exactly `L` real elements, or a list/tuple of exactly `L` real scalars; at most `L` elements are read), objects with `__array__`, generators, nested/wrong-length sequences, Booleans, strings and `ndarray` subclasses are refused typed WITHOUT conversion; then the memory admission counts the `(L, N)` result, the `(N,)` comparison rows and the L-sized conversion lifetimes (`3 * 8 * L` bytes: up to two L-double arrays plus the L-byte finite mask of the accepted `subsurface._layer_array`); only then is that conversion made (finite values) and the per-cell range checks run. A refused admission therefore converts and allocates nothing (with `memory_budget_bytes = 0` the previous order created an owned theta copy first).
* **`spatial_storage_m3`.** The total depth and the volume (`depth x cell area`) are computed with errors suppressed and must be finite, otherwise `SpatialLayerError` (a `SubsurfaceError`) is raised instead of returning `inf`/`nan`: a finite valid state can still have an unrepresentable global volume for a huge area, and a state that holds non-finite water (construction only copies; values are checked by the next step) has no storage. Inactive cells are excluded before the sum, so a huge value there does not poison the active total. `spatial_moisture` is an elementwise ratio and is unchanged (finite for a valid state).

### Owner binding and purity
A `SpatialSoilState` carries the `sha256` (parameter inputs + mask + area) of its column; any other column (different geometry, properties or mask) refuses it (`identity mismatch`), an equal parameter set prepared twice is accepted. The state array is read-only and owned (a copy); steps never write the state, the forcing, or the retained maps (hash-checked, also on refusal); a refused step publishes nothing. Order of checks: column/state types and backend, state metadata and finite time, `dt`, candidate time, forcing metadata, memory admission, then the body (values in the staged flags), then the existing packet/closure resolution.

## Memory (modelled host bytes; excluded: caller state/forcing, the owner's retained maps, interpreter/allocator state)

Every allocating entry takes an explicit `memory_budget_bytes` (required), optional `reserve_bytes` and an injectable `available_bytes_fn` (default the host `sysconf` reading); the requirement plus reserve must fit both before anything is allocated; nothing is raised silently (the A1 preparation budget does not authorise these calls).
`step`/`step_with_recharge`: outputs `(LN + 2(L-1)N + 4N + ROW_COUNT*N)*8` B (state, percolation, diffusion, four flux vectors, the four packet rows); scratch `(NUMPY_SCRATCH_DOUBLES_PER_CELL + SPATIAL_ROW_TEMP_DOUBLES)*N*8 + SCRATCH_MASK_BYTES_PER_CELL*N + packet + 64 KiB` with the common estimate's `16` scratch doubles and `SPATIAL_ROW_TEMP_DOUBLES = 8` extra `(N,)` rows (at most a few derived rows are alive at once: the lazily derived `sat_m/res_m/cap_tol` rows live for one statement; the flag temporaries and the diffusion-stage temporaries are those of the common estimate); caller inputs excluded and listed: `(2LN + N)*8` (state, added, potential rate), the pulse step `(LN + N)*8`, `+ N*8` for a share. The result coexists with the caller's state (both resident). No internal zero-forcing tensor, no history, no `(L, N, K)` array and no permanent `(L, N)` derived map exists. State helpers: `state`/`moisture` one `(L, N)` array, `uniform_state` one `(L, N)` array + `8N + N` comparison rows + `24 L` conversion bytes, `storage` one `(N,)` accumulator and one mask. Warm `tracemalloc` (compile-free NumPy, `N = 40 000`, `L = 1, 3`, both modes, CELL and mixed layouts, ordinary/share/pulse variants) measured peaks of 41 %-60 % of the modelled requirement.

## Limits
NumPy reference only; a numba/cuda-prepared owner is refused. Fixed explicit parameters: changing geometry/properties means preparing a new column (and constructing a matching state: no interpolation). No moving frame, no water fate, no PTF, no K averaging, no wetting-history rule, no LEAF/T, no operators (matrix/preferential/transpiration), no lifecycle/storm/checkpoint, no performance claim. The three old helper entry points keep the typed `_check_column` guard (S2-A.1 correction01).
