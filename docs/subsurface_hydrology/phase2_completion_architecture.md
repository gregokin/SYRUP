## 0. Approved science that this plan implements

* **Refresh.** Texture feedback is held during an event. At the transport-event handoff, refresh ONLY affected columns, even if the net elevation change is zero (a composition change alone triggers it); unchanged properties are reused. Real full rain/recession completion and truthful returned surface water come first. A refresh never reroutes hydraulics (only the existing net-elevation threshold does).
* **Bedrock.** The FULL MAPLE voxel-grid bottom is fixed, flat and impermeable. No bedrock map, permeability or storage parameter, no rock pore water, no artificial soil, no refusal merely because floating layers reach rock. Only actual soil portions store water; fully-rock portions have zero capacity and zero root-water supply. Displaced capacity is handled by the agreed reconciliation/surface return. The configured OPEN lower boundary applies only to a hydrological profile that ends ABOVE rock and is explicit export below the modelled profile, never transmission through rock; at rock the bottom behaves closed.
* **Roots** follow surface-relative layers with fixed fractions; no reallocation/plasticity when a requested layer has no soil water.
* Retained: fixed nominal floating layers, per-layer water preserved through geometry reassignment, FC ≠ SAT, FC cascade with open export once / closed excess to surface, SR2006 explicit inputs, gravity always on in new production, unsaturated initialisation only, persistent Green–Ampt history retained (no reset).

## 2. Slice C — pure bounded Saxton–Rawls (2006) provider

Module `soil_texture_properties` (+ `_numba`, `_cuda`; documented in [phase2_texture_properties.md](phase2_texture_properties.md)). Implemented as an author-verified CPU component (see that page for the exact status); not Root-qualified, no native adoption.

* **Inputs (explicit, no default).** Mandatory sand/silt/clay fractions, organic matter percent, and `bulk_density_kg_m3` (SI, converted to the paper's g/cm³ inside). The density factor DF is COMPUTED (`rho / rho_normal`), never a second mandatory caller input. Optional MEASURED anchors (`theta_1500`, `theta_33`, `theta_saturation`, air entry) replace the final anchors and optional measured Ks (> 0) replaces Eq 16 only, with full validity checks; dependencies are recomputed. There is NO second prescribed-mode engine: a directly measured field capacity/Ks without a claimed curve stays the existing explicit `spatial_layer_spec` path.
* **Distinct values**: θ33 anchors Eq16 (`Ks = 1930 (SAT − θ33)^(3−λ)`); θ6 (FC at 6 kPa) is the Tietjen field capacity; `θ6 = θS` when ψe ≥ 6 kPa (valid, flagged, never a Ks = 0).
* **Air entry**: exact 0 accepted; refuse ψe < 0, non-finite, or ψe ≥ 33 unless a valid measured air entry is supplied (never clamped). ψe is evaluated from the normal-density Eq 3 input and held fixed under density adjustment (declared recipe assumption, not a full-SPAW identity claim).
* **Refusals, not clamps**: non-finite/out-of-range/non-closing fractions (existing derived FP bound), clay > 0.6, OM ∉ [0,8] %, ρ ∉ [1.0,1.8] g/cm³, computed DF ∉ [0.9,1.3], final θS − θ33 < 0.005, anchor-order failures, unsupported air entry, nonzero coarse (no gravel/coarse input exists).
* **Size**: shared inputs/outputs O(L); cell inputs/outputs O(LN) (FC6, θS, Ks + optional diagnostics); cold computation chunk-bounded; no beds/histories/per-step transfers. Not accepted by the provider: the native bed class → (sand, silt, clay, OM, density) mapping and packing/porosity consistency remain later required qualification (slice E).


## 3. Slice D — zero/partial soil layers above the flat impermeable base

Representation (proposed; smallest sensible): keep the user's FIXED nominal layer thicknesses `dz_l` (shape never changes). Retain ONE per-cell soil-depth map `D_c` (O(N)), taken from the already exposed `represented_depth_m` (sediment height above the flat bottom face of voxel 0) at changed-cell updates, and compute per layer on the fly `h_lc = max(0, min(e_{l+1}, D_c) − e_l)` (exact overlap; zero denominators skipped), so a layer is full, partial or zero soil. Stored capacities: `fc_lc = theta_fc h_lc`, `sat_lc = theta_sat h_lc` with the same rounded products as the existing readers; a zero-soil layer has zero capacity and zero water, contributes nothing to gradients, takes no gravity and supplies no root water; no pore-water or epsilon; roots keep their nominal fractions with no renormalisation (a layer with no water supplies none). No gravity through rock: the cascade stops at the lowest soil portion and at rock the bottom is closed, so the unavoidable excess returns to surface water; the open export is applied only when the hydrological profile ends above rock.

Implementation shape: the existing kernel BODIES are shared via reader macros/compile-time variants (the A3/B2 technique): add a spatial "porous-depth" reader variant that supplies `h_lc` instead of `dz_l` in the rounded products, keeping common/historical arithmetic byte-identical where `h = dz`; divisions by `dz` become divisions by `h` guarded for zero (skip). Theta used for retention/gradients is the actual porous theta of the soil portion (`W / h`) versus the nominal root layer; a zero-`h` layer is excluded from interface conductances/diffusion. This requires new spatial-column variants (a distinct owner/record, e.g. a "floating profile" column) rather than loosening `FLAG_DERIVED` of the existing owner; the existing owner and its tests stay unchanged. Estimated memory: `D_c` N doubles plus the A1 retained maps; no `(L,N)` thickness tensor. Acceptance: zero/partial/full layer equality tests against an independent Decimal/analytic profile, masks/all-inactive, `h` at the exact edge, conservation, NumPy/Numba/CUDA agreement, no invalid parameters or fake classes, per-step cost unchanged for full-soil columns.

## 4. Slice E — native changed-column handoff, staged conservative capacity reconciliation, restart

1. **Handoff (changed columns only).** At the transport-event handoff, find columns whose composition/texture or soil depth changed (MAPLE commit evidence from `commit_bed`/`BedCommit`; do not copy the bed or histories), re-derive texture through the extended `build_soil_profile_texture` mode, refresh C properties and `D_c` for those columns only (updates O(L·C), C = changed columns), reuse unchanged properties, and trigger no routing (only the existing net-elevation threshold does).
2. **Staged transaction.** Stage new properties with `W` retained per layer; run the EXISTING top-down FC cascade once on the NEW capacities before final validation: open-above-rock bottom exports above new FC through all layers exactly once (external); closed or rock bottom: capacity-limited downward redistribution and the unavoidable excess returns to surface water (internal to surface + soil), not early if deeper storage can accommodate it. One carry per cell through L layers; no duplicated normal drainage/E/T/diffusion/rain/day or fake time; adoption is atomic (no partially accepted state), with generation/duplicate-once binding.
3. **Native operator.** An explicit spatial native profile/operator parallel to `prepare_layered_storm` (not a fake `SoilColumn`, no broad fallback) consuming the porous variant of the accepted B-slices; the original common path stays for historical runs. A conservative closure `inventory_before + rain + other inputs = inventory_after + runoff/export + bottom export + E + T` with surface return internal.
4. **Order with events.** Full actual rain/recession completion (per-step drainage already runs during rain/recession) → surface truthful → handoff refresh → interevent; properties held within an event.

If the native integration cannot be made correct merely by composing the pure components (for instance because `layered_storm`/`water_lifecycle` hard-require the common column types), that is stated up front: it needs the explicit spatial native operator above and new lifecycle/checkpoint source versions, not adapters.

## 8. Every-N-days soil-moisture snapshot output (user requirement 2026-11-13; planned, not implemented)

User request: "Also implement an every N days save of soil moisture." Binding scope (`soil_moisture_output_requirement.json`): native bounded soil-moisture DIAGNOSTIC snapshots with a configurable positive N-day cadence supplied by the user (off unless selected), wired into the actual qualified daily driver/CLI as appropriate, SEPARATE from full restart checkpoints.

* A snapshot stores the accepted per-cell/per-layer water inventory, units, layer geometry/porous depth where needed, active mask or a stable reference, nominal day/date and physical time, and generation/source identities. It reconstructs the saved moisture only, not arbitrary unsaved times and not a restart alone.
* Counting: completed nominal daily INTEREVENT updates, after actual plant withdrawals and accepted day closure; transport (wind/rain) durations never fabricate daily saves.
* No automatic per-timestep save and no deep bed copies; GPU downloads only on a scheduled save through bounded staging; explicit output quotas and no-clobber atomic publication; restart-safe due-day and duplicate-occurrence handling.
* Existing checkpoints, source profiles and defaults are unchanged. No complete weather-CSV redesign is implied.
* Slice (proposed): G, after E3 (it needs the accepted day closure and the porous-depth/geometry identities): a bounded snapshot writer module, its CPU/GPU staging tests and the driver wiring, with its own independent qualification. Whole-phase acceptance includes it.
