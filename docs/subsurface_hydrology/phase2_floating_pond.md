# Phase 2 / E4b — floating-layer vertical water inside the native Pond step

Status: CPU/host author slice (NumPy and Numba owners, Dense actual MAPLE bed). Not independently reviewed, no GPU hardware run, not whole-phase accepted.

## What it is
`PondEvent(..., floating_vertical=FloatingPondVertical(owner, available_bytes_fn=...))` (opt-in; `column=None`) replaces ONLY the vertical stage of the one old coupled step. Surface router, wet laws, splash,
native pickup/transport/deposit, net-elevation commit gate, ledgers, quiet monitor and publication are the existing `PondEvent.step` body. A default `PondEvent` has the same repr, config digest
(`bdd0fc47…f44a8` pinned) and numerics (4-step splash state digest `50c0c24a…b719` pinned, equal to the pre-edit source).

Per hydraulic step the vertical has the order of `layered_storm.layered_step` on the floating bodies: pool = H0 + rain·dt → floating preferential (optional) → floating Green–Ampt matrix
(`standing_before = H0`, onset = actual rain) → floating gravity step with zero added water and zero PET → pool + saturation return → genuine `CpuSurfaceRouter` / `NumbaSurfaceRouter`,
composed by `compose_hydraulic_step(SurfaceStep, ColumnStep)` with a real `ColumnStep` of the floating fluxes. No `ColumnParameters`, no zero-K bucket.
`HydraulicState.soil_water_m` is only the derived `(ny, nx)` layer sum; the authority is the stage payload found by the identity of that array (foreign/stale states are refused; the sum is re-checked bit for bit every step).
Rejected trials leave the accepted payload untouched (append-only weak registry).

## Touched-column depth (hot geometry)
After the real exchange and before commit/quiet/publication, columns with a GROSS exchange (pickup + deposition > 0 in any class, net-zero turnover included) are re-read with the native canonical depth
(`native_floating_soil.read_canonical_depth`: the cold compact reader restricted to those cells, no texture/property pass). Only columns whose `D` differs get an O(N) official geometry view
(`floating_soil_layers.floating_geometry_view`: every map but the depth and strict bottom flag shared; minted generation identity `identity_kind="geometry_view_token"`, never a content digest; a view of a view binds the
original prepared column). Operators/history rebind with `rebind_matrix_geometry_view` / `rebind_preferential_geometry_view` (shared sealed arrays; J and cumulative intake bit for bit; nothing reset, copied or hashed).
Only columns whose slabs or strict bottom flag change (E3c `_geometry_changed`) run the zero-time FC cascade/saturation return of the single D1 body in compact batches; a raw depth change below H alone drains nothing.
Returned water joins the actual local surface depth once; bottom export leaves once; both enter the water ledger (saturation return / drainage) so soil and surface closures stay exact. Properties are held during the event.

## Limits
CUDA is refused with typed errors. `PondEvent.finalize` (the dry reset) is refused for a floating vertical. No restart, daily or output contract.
Cost per touched step: one O(N) depth-map copy, one bounded compact read and one O(L·N) validation of the continued state; the compact reconcile still uses the cold `prepare` on ≤ `batch_cells` sub-columns (measured by the tests).
The returned-water test uses a labelled fault-injected depth source (a 6 mm lower canonical depth) because physical µm-scale erosion per step never changes a slab by enough to return water in a small fixture.

## E4c (CPU slice)
- `floating_geometry_view` now ALWAYS admits its owned O(N) maps and validation scratch (the caller's reader, else the real default host reader; the reserve is validated on every branch; the CUDA current-device gate runs first).
- Native Windowed bed (CPU: NumPy/Numba): the touched-column depth is the genuine native prefix path `windowed_committed_surface_elevation_m(..., trusted_packet=True)` (bitwise the Dense NumPy canonical depth; no resident floor, no deep read, no copied decoder), valid along the native producer chain (cold full-validated initial bed via the witness check, then the Pond's own native descendants). Step and terminal hooks run before the commit/quiet/publication, which stays LAST. Tests compare Dense and Windowed twins bit for bit (W, J, depth, derived soil, audits) through wet+splash exchange and a real terminal settlement.
- NOT implemented: CUDA (device hot geometry view, selected zero-time reconcile with an explicit operation mask, device canonical depth, `CudaSurfaceRouter` composition, device payload/transfer counters). The GPU definitions file still contains the refusal pin and strict-xfail equivalence definitions.

## E5 (CUDA, Dense and Windowed device beds) — author-written, NOT run on a device
`FloatingPondVertical` now accepts a CUDA native owner (`floating_pond_cuda.py`). Same stage, same `PondEvent.step` body; no new physics or kernels.
- **Solver:** genuine `CudaSurfaceRouter` (`step(SurfaceState(t0, pool + return, qx, qy), dt)`, accepted start time) composed by `compose_hydraulic_step` with a real `ColumnStep`; the floating matrix/preferential/gravity bodies are the CUDA D1/D2 owners with zero E/T. `soil_water_m` is the derived device layer sum (registered, re-checked each step with one counted 8-byte read), never an authority. Real device arrays only (no `np.asarray` of CuPy).
- **Hot geometry:** the D3 qualified helpers: `floating_geometry_view` (device), zero-copy `rebind_*_geometry_view`, and `reconcile_floating_selected` with a COMPLETE mask computed on the device from the actual canonical depths with the owner's slab/bottom formula on exactly the cells whose depth changed (E3c: a D-equivalent change selects nothing). Returned water joins the actual surface depth and the native bed water once; bottom export is ledgered once (step and terminal hooks).
- **Device canonical depth:** Dense: the native `sum_per_cell_numpy_order` on bounded contiguous gathered rows of only the gross-exchange cells (voxel `(B,1,V,K)`, active `(B,1,K)`), `T/rho/area + active/(rho*area)` through the native helpers; the qualified extent (`V*K <= 32768`) is preflighted once at the cold handoff and an unsupported shape is refused. Windowed: `windowed_committed_surface_elevation_m(trusted_packet=True)` on the device packets.
- **Quotas:** two separate pools (device `available_bytes_fn`/`reserve_bytes`/`memory_budget_bytes`; host `host_*`, CUDA only: meaningless on a CPU owner and refused); real default readers; reserves counted once by `fcu.admit`; the current device is gated first. Composed models cover retained buffers, live payloads, the step (three stage results + surface) and the exchange (selected reconcile, state checks, gathered rows / prefix decode).
- **Declared transfers per exchange:** one `flatnonzero` count, one 8-byte count each for `moved` and `changed`, then the D3 packets (view 32 B, selected 8+8+32+56+32 B); no W/J/map/depth/mask download. Cold: one host active-mask record, one depth upload, the source witness.
- **Verified here (host double only):** `tests/phase2_floating_pond_cuda` runs the CUDA exchange stage against the CPU stage on the same native bed (depth bit for bit, water 2e-12/1e-14, real returned water), net-zero/D-equivalent no-op, admission gates, CPU-argument refusal and the Dense preflight. The real device tests (`tests/phase2_floating_pond/test_gpu_definitions.py`) are Root's.
- Limits: unrun on hardware; the end-to-end CUDA `PondEvent` (CudaSurfaceRouter, MAPLE device sediment, device Windowed publication) was never executed by the author; `finalize` still refused; no restart/daily/output.

### E5 correction01
- **Host model (constructor, CUDA).** Dimension-aware cold HOST requirement admitted from the host pool BEFORE the mask readback: `2 N` (mask download + contiguous staging) + `8 N` (host depth record staged for the one-off upload) + `2 (L + 1) 8` (edges and their copy) + the declared 4096-byte hot-operation side, plus `fcu.admit`'s 64 KiB Python allowance and the single host reserve; retained afterwards: `N + (L + 1) 8`. The cold source-witness scan of `check_initial` is admitted from the HOST reader (explicit `host_available_bytes_fn`, else the real default host reader) and host reserve, never the device reader. Excluded: interpreter/JIT/allocator pool, the owner's existing host arrays, whole-process memory.
- **Canonical contract.** Dense: voxel total and active total both through `sum_per_cell_numpy_order` (`trailing_axes` 2 and 1) on bounded contiguous gathered rows, `T/rho/area + active/(rho*area)`; the native `compute_active_layer_actual_thickness_m` (a raw device sum) is no longer used. Windowed: the native prefix total (`windowed_committed_height_total_kg`, `trusted=True`) with the native `_elevation_from_total_mass`, plus the SAME ordered active thickness (the native whole-grid wrapper is no longer used). The extent preflight (`preflight_depth`) covers both representations once at the cold handoff. Genesis of a Windowed device bed stays canonical host dense baseline -> device packets.
- **Counting statement.** Counted through MAPLE's instrumented `to_host`: the `scalar()` reads (moved/changed counts, the derived-sum equality) and the declared diagnostic downloads. NOT counted by MAPLE's instrumentation (implicit CuPy synchronising copies): the `cupy.flatnonzero` count, boolean-mask indexing (`ridx[differ]`, `d[moved]`), `.astype` on index arrays and the native reducers' own internal launches. These are bounded by the gross-exchange count and measured only by Root's hardware controls.
