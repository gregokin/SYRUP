# Genuine event-completion record
The native Pond producer now registers an exact completed handoff/state pair only after its retained-water completion checks and closing audits. Its `completion_capability` API and the floating vertical's read-only `event_end_bundle` expose the current W/J/I/D and surface/bed references without copying arrays. Caller-built handoffs, stand-in producers, incomplete/ordinary states and consumed completions are refused. A functional trial does not invalidate an earlier accepted completion.

This is producer completeness only. Adopted-parent lineage, selected property refresh, subsequent event opening and daily/restart handoff need their own integration. Arrays follow the existing immutability convention; deliberately mutating private producer registries is outside this contract. The capability holds its referenced state while the caller retains it; the producer registries are weak and do not accumulate old beds.

Root independently verified 146 CPU checks and two actual CUDA native Dense/Windowed completion cases against MAPLE 9f466d2cfcd52991b24496cf67f4562d6268afa9. The original public-mint bypass was reproduced at native step zero and is now typed-refused. See `phase2_event_completion_acceptance.json` for exact frozen sources and limits. No change to rainfall, water/sediment equations, routing, old checkpoint profiles or defaults is implied.
