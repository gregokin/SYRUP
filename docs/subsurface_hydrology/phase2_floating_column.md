## Geometry and owner

Shared nominal edges `e_0 = 0 < ... < e_L = H` (O(L)) and an actual soil depth `D_c >= 0` per cell (O(N), caller input; never a world datum or a bed scan). `h_lc = max(0, min(D_c, e_{l+1}) - e_l)`; for `D_c >= e_{l+1}` this is exactly the
historical `e_{l+1} - e_l`, so a full slab is bit-identical to the nominal `dz`. `bottom_open_c = (configured open) AND (D_c > H)`; `D_c == H` is physically closed rock; a configured closed bottom is closed everywhere. No `(L, N)` thickness,
capacity or conductance map exists: the owner retains only RAW maps (theta residual/FC/SAT and the interface input by scalar/shared/cell layout, `D`, mask, edges, nominal dz and separations) read-only, with a cold SHA-256. `FloatingSoilColumn`/`FloatingSoilState`
are new types (not `SoilColumn`, `SpatialSoilColumn`); every legacy/spatial/native entry refuses them and they refuse legacy objects. Gravity drainage is always on (not a parameter).

## Documented kernel arithmetic (all backends; stage order unchanged)

Rows per cell: `dz[k] = h_k if h_k > 0 else 1.0` (a finite stand-in, unused where `h = 0`), `res_m/fc_m/sat_m = theta * h`, `cap_tol = coef * (theta_sat * h)` (`coef = volume_roundoff_bound_m3(8, 1)` as `soil_layers`), `pair_inv = 1/dz_k + 1/dz_{k+1}`,
pair separation `sep = sep_nominal[k]` (the historical centre difference) when `D >= e_{k+2}` else `(h_k + h_{k+1})/2` (1.0 where both are 0), conductances `G_down = ((d K) dz_k)/sep`, `G_up = ((d K) dz_{k+1})/sep` (donor-depth law with the ACTUAL donor depth) or `D_k/sep`,
factor `-expm1(-((G s) dt))`. Stages: addition with saturation return; gravity (FC triggers movement; closed/rock bottom: `forward = min(excess, deeper room)` with the room measured once on the post-addition water, bottom layer forwards nothing; open above rock: forward all, the last
excess is the exported `drainage`); layer-0 evaporation (`theta0 = W/dz`, an all-rock cell has `theta0 = 0 <= residual`: demand 0, E 0, unmet 0, like a dry surface); sequential pair relaxation (an interface touching a zero slot cannot exchange: the donor/receiver limits are exactly 0; the compiled kernels skip it);
output/closure checks with MAPLE's bound. Inactive cells: published policy `INACTIVE_POLICY` (finite, non-negative placeholders; no capacity law; preserved bit for bit; excluded from conservation). NumPy runs `subsurface._reference_step_body` through a private typed reader; because
that body's lower-boundary flag is per call, it makes one pass per boundary kind present and merges per cell (mixed domains hold a second result set transiently); Numba/CUDA take the flag per cell.

## States and reconciliation

`floating_initial_state`: active cells strictly `0 <= W < sat_m` on porous layers, exactly 0 on rock slots (a wholly-rock column is legal). `floating_continued_state`: `0 <= W <= sat_m + tol`. No epsilon. `floating_moisture` returns `W/h` (0 where `h = 0`).
`reconcile_floating(old_column, old_state, new_column)` is a PURE zero-time candidate (no added water, E, T, diffusion, rain, clock, fake dt): the existing downward FC cascade on the NEW field capacity (closed/rock: capped by deeper room measured once; open above rock: the last
excess is exported once), THEN the saturation excess of each layer returns to the surface; no upward soil fill, no clipping. The candidate carries percolation, surface return, bottom export and a receipt (old/new column identities, water digest, closure residual vs the MAPLE bound); the minted state must be a valid
continued state of the new column. A state at/below the new FC and SAT is unchanged (identity, no flux); the native adapter (E) must skip reconciliation when no hydraulic capacity changed and owns duplicate-generation authority.

## Memory model

Retained = raw maps by layout + `(L+1) + L + max(L-1,1)` doubles + `N` doubles (D) + `2N` bytes (mask, bottom-open). One NumPy/Numba step = `subsurface.estimate_step_memory` (shared body) + `FLOATING_ROW_DOUBLES (16)` N-rows + one sanitised `(L, N)` water copy + a second result set for the mixed-boundary merge.
The reduction packet is the shared 9-double (72 B) packet. Measured warm host peaks for N = 20 000, L = 3, mixed rock/open/closed: NumPy 7.2 MB (model 11.7 MB), Numba 2.4 MB (model 9.5 MB); retained model 1.96 MB.

## Limits

No CUDA backend (source only; needs device owner maps, device-side validation packet, current-device guard, admission, launcher, one-packet reduction, hardware qualification); no D2 matrix/preferential/T guards (a fully-rock cell's infiltration is NOT claimed); no native mid-event rock-depth updates, dirty-depth tracking, windowed beds, source locks or checkpoint;
the NumPy reference is not the performance path (mixed domains cost two passes). Whole-phase completion is not claimed.

## Continuation01: shared compiled bodies (engineering choice, 2026-11-13)

* **Numba**: `subsurface_numba._build(numba, common, floating=False)`; the floating variant is dead-branch pruned out of both historical variants. It reuses the existing 40-argument signature through a documented private binding (`floating_launch`: `dz` = shared edges, `tol` = per-cell soil depth, `pair_inv` = nominal separations,
  `g_down` = raw interface input, `g_up` = per-cell bottom-open 0/1 flags, `res_theta0` = donor coefficient), binds `h`-derived locals per cell (`bind_floating`), reads the lower boundary per cell, flags input capacity only on ACTIVE cells, and gives an interface touching a zero slot the factors 0.0. The gravity block is now the module-level
  `_gravity_stage_py` (statements moved verbatim, jitted inline into the step and the reconcile kernel): one copy of the cascade equations. The default common/spatial variants are held bit-identical by the existing pre-A3 comparison suite (141 passed) and the subsurface suite.
* **CUDA**: `render_step_source()` = `sc.render_body_source(FLOATING_READERS, FLOATING_STEP_HEAD)`; no layer bound, no per-thread array: `HP(l)` is evaluated in registers from the O(L) edges and O(N) depth, `DZ` is the finite stand-in 1.0 only where `HP = 0` (arithmetic only), `FAC/FAC_UP` return 0.0 before any
  division at a zero interface, `GUARD_INVALID_LANE` declares the per-cell `bottom`, and `SAT_M` is `DBL_MAX` on inactive cells. `render_reconcile_source()` slices the gravity block and the saturation-return loop out of `sc._BODY` by exact anchors (each must occur exactly once: fail closed) and emits gravity THEN saturation return.
  `provenance()` hashes the shared body, both slices, the readers and the rendered source. Verified only by g++ host execution against the NumPy/Numba results (step 2e-12; reconcile bitwise). ## D1b: resident CUDA execution (2026-11-13; written without a GPU, host-verified only)

New execution helper: `src/maple_syrup/floating_soil_layers_cuda.py` (launchers, admission/device gate, memory terms, cold hash; no physical source). Kernels: `subsurface_cuda_floating.render_resident_source()` = the ONE shared body `subsurface_cuda._BODY` through the floating geometry readers with a
contribution epilogue (all-lane wrapper, fixed block tree, one-block finalize: the spatial S2 pattern), reconciliation from the anchored slices of that body, resident validation kernels and utilities. No fixed layer bound, no per-thread layer arrays (only the 7/4 contribution doubles), no full-width rows, no CUB/CuPy reduction.

* **Owner (`prepare_floating_column(..., backend="cuda")`)**: per-cell inputs are CuPy arrays of ONE device (no implicit transfer); the O(L) edges are a host array uploaded once (counted). Order: the CURRENT device is gated first (typed refusal, never a selection), then metadata, host validation of the edges, admission (device and host separately, with reserve and truthful readings), device-to-device copies, the resident validation kernel (ONE 32-byte packet; nothing is published on a flag), the bottom-open flags (`configured open AND D > H` on the device) and a COLD streamed identity hash through one bounded host buffer (separate declared traffic). `n_active` is not computed (no reduction). Logical immutability by contract; NOT external tamper-proofing.
* **States**: `floating_initial_state/continued_state` copy privately on the device (D2D) and validate with ONE 32-byte packet (strict initial policy, rock exactly 0, inactive placeholders finite and non-negative). States carry a minted `token` (a generation/capability identity, never a content hash).
* **Hot step / pulse step**: no host-to-device copy; ONE 72-byte device-to-host packet (raw 9 x uint64 and the rebuilt nine-value float packet are both counted in the host model, 144 B); `subsurface._resolve` applies the existing closure bound and typed errors (`SubsurfaceFitFailure` for a pulse that does not fit).
* **Hot reconcile**: ONE 56-byte packet (five totals: before, after, surface return, bottom export and the ACTUAL moved percolation); NO download or hash of water/properties; the receipt is versioned `identity_kind = "capability_token"` (old/new state tokens, cold column/mask/edges identities) with `water_sha256 = None` and the measured finite `moved_percolation_m3` (one more scalar of the same block reduction). The CPU receipt keeps `identity_kind = "content_sha256"` and its full content digest (cold, deliberate). Native adoption (E) binds generation/once-only.
* **Queries**: `floating_moisture` (device array, 0 where `h = 0`) and `floating_storage_m3` (fixed tree, one 8-byte read).

### Memory model (device payload bytes; allocator rounding, NVRTC, the context and interpreter excluded)

Retained: raw theta maps + interface by layout, edges `8(L+1)`, nominal separations `8 max(L-1,1)`, soil depth `8N`, mask `N`, bottom-open flags `N` (tested equal to the owned payload). State copy `8LN`. Step outputs `(LN + 2(L-1)N + 4N) 8` + scratch `7 * 8 * nb + 72`; reconcile outputs `(LN + (L-1)N + 2N) 8` + scratch `5 * 8 * nb + 56` (`nb = ceil(N/128)`); validation 32 B. Host per hot call: step 144 B, reconcile 112 B (raw 56 + rebuilt 56), checks 32 B, cold hash buffer `HASH_CHUNK_BYTES` (1 MiB), plus a 64 KiB allowance. Static shared memory per block (source-derived): step 7168 B, finalize 14336 B, reconcile 5120 B. Verified on the double: allocations per step equal the model exactly and repeat identically (plateau); at N = 50003, L = 3 a step allocates exactly 4,422,232 B (outputs 4,400,264 + scratch 21,968) per call, three repeated steps allocate the same, and three steps read 3 x 72 bytes and upload nothing.

## D1b correction01 (2026-11-13)

1. **Cell area.** `reconcile_floating` now requires EXACTLY equal `cell_area_m2` in the old and new columns on every backend, checked before any quota reader, allocation, state read or kernel; inventories are never rescaled and the receipt can no longer mix areas.
2. **Old-parent admission.** The accepted old water must satisfy its OWN owner (finite and non-negative everywhere incl. inactive placeholders; on active cells within the OLD porous capacity `sat_m + tol`, rock slots empty). Exceeding the NEW capacity stays legal only inside the stage. `FloatingSoilState` is an ordinary frozen dataclass (not factory-only), so the check is made by the reconcile itself: CPU/Numba with the same value checks as the state constructors; CUDA inside the existing per-cell reconcile walk (old soil depth + old saturation map read as two more kernel arguments, flag bits 20/21 in the existing packet, no download, no temporary), raised before any state is minted. The state `token` is not a proof and is not used as one; native adoption (E) binds real parent/generation authority.
3. **Moved percolation.** The receipt's `moved_percolation_m3` is a measured finite value on every backend: on CUDA the per-cell sum of the interface forwards is a fifth contribution of the SAME block reduction (packet 7 words = 56 B, static shared 5 x 8 x 128 B; admission, host model and tests count it). The STEP packet/source ABI is unchanged.
4. **Default Numba code generation.** The jitted inline gravity helper of the first D1 form added reference-count traffic to the per-cell path of the DEFAULT common kernel (LLVM `NRT_incref/decref` 28/71 vs 24/66; warm ratios 1.09-1.26 on my controls). The step kernel is restored to the historical gravity block (per-cell `bottom` for the floating variant is one pruned assignment before it), and the floating reconcile kernel is GENERATED from a fixed trusted template and that very block (`subsurface_numba.floating_reconcile_source`: fail-closed anchors, hashed provenance, no user code): one copy of the cascade equations, default code generation equal to the frozen G0 C3 kernel (24/66; warm ratio 1.00).
