## Correction01
* **Namespace classification.** Export now classifies each array with MAPLE's `is_device_array` (a CuPy array) and treats EXACTLY `numpy.ndarray` as host; anything else is refused (`_is_device`). The earlier `hasattr(a, "device")` was wrong on NumPy 2.x, whose arrays also carry `.device == "cpu"`, so host config arrays went through the counted `to_host` helper (Root measured 208 B = 24+96+24+24+24+16 of host thickness/grain/OM/latent FC/SAT/diffusivity arrays). Host config arrays are now plain owned copies under the host quota; only CuPy maps use the counted chunked D2H. Chunk bytes, no-W/J/I and the scalar rules are unchanged.
* **New GPU definitions** (unrun): a genuine native resident-window GPU context (`dense_deep_bed` + `windowed_counterpart(xp=cp)`, six-grain Pond config, real NativeOwner and FloatingPondVertical) export/parse/reconstruct with bit-exact ids, D0 and Ks (explicit and texture-Ks); all-zero and partly-disabled species receiving weights (background separate) restoring the exact original preferential sha. The previous `cuda_vertical` fixture is Dense four-grain only. Shared FC/SAT layouts remain documented as unexercised (the native pipeline does not produce them; no fake owner is used to force them).

## Correction02 (test/doc only)
