# Phase 2 matrix infiltration — bounded combined actual intake (S2-B2.c review02, numerical correction)

Status: author-written CPU only, uncommitted, awaiting Root's independent review and hardware runs. Not a new physical law or policy: the candidate law, onset, unponded/prepond/ponded rules, Newton solver, tolerances, flags and parameters are unchanged.

## Defect
The ponded actual is bounded separately (`post = min(c2, pool - pre, room - pre)`), and the unponded actual `pre = min(r t_u, pool, room)`. In FP64 their recombination `intake = fl(pre + post)` can exceed the pool (or the room) by one ulp (`fl(pre + fl(pool - pre)) != pool`). On the pool this gave `pool_out < 0` and a negative rejected amount, which the strict output check (bit 17) refuses — for VALID inputs, in the common NumPy, Numba and CUDA bodies and every spatial path that shares them. Root's two minimal single-column controls (`root_s2_b2_c_minimal_refusal_controls.json`): pool `0.04838095732241791` → intake `0.048380957322417914`, and pool `0.029264621197886812` → `0.029264621197886816`.

## Correction (one body per backend; NumPy, Numba and the shared CUDA body)
After `pre` and `post` are formed as before: `intake = pre + post; intake = min(intake, pool); intake = min(intake, room)`; `pre` is unchanged; ONLY when that bound reduced the intake (and the cell ran the ponded phase) the ponded actual is re-derived, `post = intake - pre` (>= 0 exactly, since `pre <= pool` and `pre <= room`); the history advance `post / g` (g > 0), the soil credit, the pool debit, the ledger (`+ intake`) and the diagnostic rows use these SAME actuals. Where the bound is inactive no value changes: results are byte-identical to the previous arithmetic (verified on 4 x 60 000 identical cells per backend: all differences are confined to the cells where the OLD recombination exceeded a bound — 69 cells per backend). The returned candidate is unchanged and rejected potential never enters the soil. No epsilon, no post-hoc clipping/erasure of a negative, no tolerance, bound or guard change; the saturation capacity is not increased (the top layer fills to exactly `theta_sat dz`).
Arithmetic note: `post = fl(intake - pre)` is exact only when `intake/2 <= pre <= intake` (Sterbenz); otherwise `fl(pre + post)` may differ from `intake` by one ulp. The authoritative actual is `intake` (the quantity the soil, pool and ledger use); the rows `pre`/`post` and the history advance agree with it to rounding, inside the existing closure bounds.

## Memory
No new retained or output arrays, and no admitted-budget (quota/estimate) increase. The NumPy body does hold two transient boolean masks (`N` bytes each) while the bound is evaluated and keeps the existing `room` array alive a few statements longer; these are short-lived temporaries inside the already-admitted scratch allowance, not new persistent state. The measured NumPy step peak (tracemalloc, N = 50 000, L = 3) is identical before and after (15 955 632 B against the unchanged 29 200 544 B model); Root separately verified the unchanged admitted peak. Numba and CUDA add scalar comparisons only. No quota was raised.

Valid inputs now integrate where the old source refused or silently overshot by an ulp; every behaviour change is confined to cells whose old recombination exceeded the pool or the room.
