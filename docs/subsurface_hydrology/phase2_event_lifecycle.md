# Phase 2 / EB3 — single-authority floating event lifecycle (`floating_event_lifecycle.py`, CPU)

Architecture and the durable held-law-root strategy are in the module docstring. Summary: `open_floating_event` (owner retired LAST, vertical detaches the stale W0) -> `Occurrence` head -> real native storm -> genuine EB1 completion -> `close_occurrence` (EB2 staged selected refresh + audit, boundary of CURRENT references, capability consumed LAST, head replaced LAST) -> `Boundary` (`boundary` or `pending_recession`) -> `begin_occurrence` (`FloatingPondVertical.from_boundary` + `PondEvent.continued_state`, which carries the last actual routing reference). A refreshed property generation is a public prepared root (canonical identities) whose water-free held facts reproduce through the public H0 export/reconstruction; the cold source anchor stays the original witness and the execution epoch is a separately labelled chain, never a content hash. Not implemented here: wet/dry day, wind adoption, physical file codec, CUDA. See `report_event_lifecycle.md`.
