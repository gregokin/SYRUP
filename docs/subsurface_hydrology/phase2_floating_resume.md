# Phase 2 R1a — in-memory floating capture / restore

`maple_syrup.floating_resume` (new) + two additive hooks on `floating_pond.FloatingPondVertical` (`held_template()`, `adopt_resumed(...)`, and the sealed `HeldTemplate` record). In-memory only: NOT a file format, NOT a physical checkpoint, no CLI/scheduler/LEAF/calendar/growth.

```
cap    = floating_resume.capture_floating_pond(event, state, available_bytes_fn=..., reserve_bytes=0)
state2 = floating_resume.restore_floating_pond(other_event, cap, available_bytes_fn=..., reserve_bytes=0)
```
* `capture` takes a genuine wet `PondEventState` this event's vertical issued (checked by the event's own `_check_state`), refuses Windowed beds with a pending deep journal (publish through the event's own storage policy first) and mints an opaque, owned, uncopyable (no copy/deepcopy/pickle/`replace`) `FloatingPondCapture` with sealed copies of: current `W (L,N)`, `J`, lifetime intake `I`, current canonical `D`, soil clock; the HELD context (`theta_field_capacity`, `theta_saturation`, `D0`, `Ks`) and the stable root column / matrix operator / preferential `sha256`, owner config sha, generation and native source witness (the facts a later R1b dirty set needs). The parent state value is referenced (states are immutable values; a test proves it bit for bit unchanged).
* `restore` verifies producer/source pair/event config + forcing/vertical identity/backend/bed storage/shape, then that the TARGET vertical's held template equals the captured held facts bit for bit; only then builds the CURRENT payload with the public factories (`floating_geometry_view` at current `D` unless `D == D0`, `floating_continued_state(view, W, t)`, `floating_matrix_history` on the held operator + `rebind_matrix_geometry_view`, `rebind_preferential_geometry_view`) and registers it with ONE call (`adopt_resumed`, which demands a genuinely minted capture). The returned state is validated by the event's full `_check_state` and `audit`.

## Corrected design points (Root review)
* `W` is validated against the CURRENT geometry, never the original `D0` capacity: after a deposition `W` may legitimately exceed what the prepared column could hold (test builds it from a real deposition + rain; the old-style validation against the held column is refused).
* No `NativeFloatingSoil` is minted and no initial water is faked: the held template and the current payload are separate; there is one water authority.
* The property provider/texture reader/`initialize`/`stage_native_refresh`/witness/`prepare_floating_column` are never called during restore (spied); the held maps come from the verified template, so a measured override keeps its normal future semantics (owner and config untouched).
* Stable identities: root column/operator/preferential sha. The current view/operator `sha256` are generation tokens, not durable, never compared across instances.
* Explicit `available_bytes_fn` is required (no unlimited reader); budget 0 refuses before any registration.

## Correction01 (Root-reproduced blockers)
* **Integrity.** `capture.held/current/source_pair` are read-only mappings of read-only array copies, and the capture is bound to an INTEGRITY DIGEST of every captured value (scalars, identities, source pair, each array's dtype/shape/bytes, parent identity) kept in a module-private weak table; it is re-verified before every use (`require_capture`), so a replaced field/mapping/array byte (including a layer redistribution that preserves every derived cell sum) is refused. The parent `PondEventState` is referenced, not deeply sealed: an honest bounded limit (immutable value by convention).
* **Adoption.** `adopt_resumed(prepared)` accepts only a minted, one-shot, vertical-bound prepared-resume record created by `restore_floating_pond`; `floating_resume.prepared_parts` re-verifies column root/geometry/mask/area/held maps, operator/history chain, preferential, state, J/I/D/clock exactly against the capture and the held template. The free keyword form no longer exists.
* **Reserves.** `reserve_bytes` uses the existing strict `_count` rule (non-Boolean integer >= 0) before any availability read, value check or copy, on every path. The declared estimates include the integrity digest allowance.
* **Registration last.** The candidate is validated (event `_check_state` + native water/sediment audits) through `FloatingPondVertical.resume_scope`, a provisional resolution that never touches the registry; `adopt_resumed` registers LAST. Source hashes/imports are computed before the minting windows; constructors receive plain values.

## Correction02 (cold memory boundary, metadata before copy)
* **Cold source hash is modelled.** The first use in a process hashes the imported `maple_syrup`/`maple` trees (`provenance.source_tree_digest`: a 1 MiB read buffer plus walked-file metadata; measured 1.48 MB with caches empty). Capture and restore now add `provenance._READ_CHUNK_BYTES + COLD_METADATA_ALLOWANCE_BYTES (2 MiB)` to the SAME admission, only while a process-local source cache is empty (warm = 0, never charged twice), and admit it BEFORE the source pair is computed (restore moved its admission above `_source_pair`). Nothing is pre-warmed, the source guard is unchanged, and the figure is not a whole-process claim (`HASH_ALLOWANCE_BYTES`, the event validation working set and interpreter overhead stay outside the model).
* **Metadata first.** `require_capture` checks exact types/keys/dtype/shape/C-contiguity of every container and array (`_check_layout`) before any byte is hashed or viewed; `_digest` uses a direct `memoryview` (no `ascontiguousarray`). Malformed captures give typed `FloatingResumeError` (no `BufferError`, no copy, no `__array__` callback); value integrity is unchanged.

## Limits
CPU NumPy/Numba floating Pond only (CUDA refused; no GPU definition is meaningful yet); Dense and published genuine Windowed CPU; the capture is process-local and not source-verifiable by a reader of a file (the later codec owns array/source verification and must mint through a legitimate factory); the target event/vertical must be built from the identical static config and held template (generation, witness, config), never from the eroded bed; dirty tracking (R1b), file codec, daily cursor/every-N and execution-receipt digest are not here.


## Reconciliation into the E5 main candidate (CUDA record unsupported)
The R1a record is CPU in-memory only (NumPy/Numba owners; Dense and published Windowed). The E5 main candidate also has a CUDA floating Pond; capture/restore refuse a CUDA vertical explicitly (`CPU_BACKENDS`), never silently. The public acceptance receipt is `phase2_floating_resume_acceptance.json` (bounded limits: no file checkpoint, no fresh-process restore, no CUDA; the restore record model excludes the native event validation/audit arrays, so no whole-process or whole-composed memory bound is claimed). `FloatingPondVertical._provisional` is initialised before both the CPU and the CUDA constructor branches.
