# Phase 2 G3 S1+S2 — floating daily lineage from an initialized soil, and the every-N moisture save

`floating_daily.py` (new), `floating_daily_output.py` (new), one tiny public helper `native_floating_soil.retire_native_owner_to_lineage`. Standalone example: `phase2_floating_daily_example.py` (genuine factories; N is an ordinary runtime argument of the example script, not a product CLI flag).

## What it is (and is not)
* Starts from a genuinely FRESH, generation-0, CURRENT `NativeFloatingSoil` and the actual `NativeBed` it was initialized from (cold source-witness equality). A refreshed or depth-only owner is refused (its binding witness need not be its property source: later freshness proof / cold refresh). No surface carry (H0 = 0); no Pond/wind state is accepted. The bed is referenced and never changed. A new `recharge.DailyCursor(run_digest)` is created: the profile's own nominal clock, no historical cursor.
* Single water authority: the lineage state's `FloatingSoilState` (W) and `FloatingMatrixHistory` (J, I). The owner is retired LAST (`retire_native_owner_to_lineage`, after every refusable construction), so it can never be staged/adopted against its stale `W0`. The held template (root column, evaporation operator, sealed zero arrays) is water-free and shared; no owner is manufactured per day.
* Transactions (pure; `expected_parent` REQUIRED, minted by `expect_parent(state)`; minted uncopyable states): `floating_daily_action`, `request_floating_withdrawal`, `close_floating_day`.
* Day: `recharge.plan_daily_rain` / `bind_forcing` / `DailyCursor` / `DAY_S` reused. P = 0 -> no-rain; 0 < P <= T (equality included) -> ONE `floating_step_with_recharge` (pulse on top, FC cascade before E, no extra drainage); P > T -> `requires_full_storm` BEFORE E/time/cursor. A recharge pulse that does not fit ANY active closed column -> `requires_full_storm` (capacity_failure) from the UNCHANGED parent with the FULL native forcing. E-only: qualified `floating_evaporation.stage_floating_evaporation` (H0 = 0), then `fsl.floating_step` once for 86400 s. Matrix/preferential are not called (zero pool), J/I stay exact; recharge is a simplified pulse, never modelled intake. Any positive surface return refuses the candidate (nothing rounded to zero; needs the native flow of a later slice).
* LEAF: aggregate `(L,N)` request through `floating_withdraw` (min(request, available) per layer, no compensation, zero time); `aggregate_sparse_demand` reduces bounded sparse (cell, layer, amount) links to the aggregate (no `P*L*N`). A request sequence number prevents a double debit; all-zero requests are legal. The day is final only at `close_floating_day`, after T: the cursor ordinal is consumed once there.
* Ledger: bounded scalars (lifetime + last day: rain pulse, E, drainage, accepted T, MAPLE-bound closure). `execution_digest` is a deterministic execution-receipt lineage digest, NOT a content hash.
* Every-N: `FloatingMoistureOutput.create/resume/notify_day_closed` (strict positive integer N, absent = off). Only the final close notifies; due days are completed nominal days N, 2N, ... from the bound origin. A due day writes W, canonical D, mask, nominal edges, area, shape through the qualified G1 writer with identities DERIVED from the accepted state (`frame_identity()`); not-due/off days touch no array. Quotas/limits explicit; sealed frames are verified, never overwritten; unknown files preserved; failure leaves the accepted parent retryable; resume cannot change N/source/run/origin and requires every earlier due frame to be sealed.

## Explicit limits (later slices)
No full storm / outlet / routing handoff, no Pond or Wind coupling, no retained pond, no day-after-storm, no event-end property refresh or current-W handoff (S4-S5), no physical (file) checkpoint or fresh-process reconstruction of the lineage (S7: the output record only binds an existing lineage), CPU NumPy/Numba only (CUDA owner refused by a typed error; device definitions only), no scheduler/CSV/LEAF growth, no complete Phase 2 claim. The capacity-failure receipt does not count the failing columns (the floating step reports only the typed failure).

## Correction01 (independently reproduced gaps)
* **Final close audit.** `close_floating_day` now audits the CURRENT native water before any mint/IO: FSL state/column binding, finite/non-negative/capacity/rock values, the accepted physical clock, and the window+lifetime closure `storage_now = initial + rain - E - drainage - T` within the ACCUMULATED MAPLE component bounds (every step's `StepBudget.bound_m3`, every withdrawal's bound) plus the MAPLE FP64 summation bound of the storage queries (`conservation.volume_roundoff_bound_m3`; no new tolerance, the earlier `4 eps N` extension is removed). The daily rain is the step budget's authoritative `added_m3`, checked against the declared recharge within the same bound. Water changed outside the accepted transactions is refused. One host storage query per close, independent of the output (not-due/off add nothing).
* **Constructor memory.** `_construction_need` is ONE composed, dimension-aware plan admitted before any owned array, cold hash or scan: scan + first-use source-pair hash (when the caches are empty) + evaporation model + every retained array (`(L,N)` zero block, `N` surface/depth, `L+1` edges, `N` mask) + one `(L,N)` storage-query block + allowance + reserve once.
* **Sparse helper.** `aggregate_sparse_demand(..., max_links, available_bytes_fn, reserve_bytes=0)`: strict metadata first, then a composed `8LN + O(K)` host plan admitted before any cast/validation temporary/dense allocation.
* **Source and physics are separate fields.** The context seals the ACTUAL imported source pair (`pond_checkpoint_source_pair`, cold once, read-only mapping) and a COMPLETE `physics_config_sha256` (all five evaporation coefficients, backend, versioned clock profile, native config, root column and matrix-operator identities, property source, area/grid); the native config, root matrix operator and Ks references are held water-free in the context. The output record (schema `/2`; v1 was unadopted and is not migrated) carries `code_source_pair`, `physics_config_sha256`, native config/column/witness; `resume`/`notify` compare the state's sealed pair and physics hash (no per-day hash). A comment-only source change in a fresh process refuses the original output; a changed `soil_factor` is refused.

## Correction02
* **Final-close admission.** `close_floating_day(..., available_bytes_fn=None, reserve_bytes=0)`: strict reserve/reader metadata, then the dimension-aware O(N) host plan (`_audit_need`: `AUDIT_DOUBLES_PER_CELL` float rows + `AUDIT_MASK_BYTES_PER_CELL` masks per cell, ledger scalars, allowance, reserve once; independent of L because the checks run layer by layer) is admitted against the REAL reader (the default host reader `subsurface.default_host_available_bytes` when none is given) BEFORE any private value check, array temporary or native storage query (the CPU `fsl.floating_storage_m3` ignores a reader, so the lineage models and admits it itself; the qualified FSL source and its default query are untouched). Zero / need-1 / a huge reserve refuse before any query, mint or output I/O; the exact need runs the audit.
* **Genuine daily window + lifetime.** The ledger carries the CURRENT day's window (`day_storage_before_m3` = the step budget's `storage_before_m3`, the day's own rain/E/drainage/T, `day_bound_m3`, `day_n_terms`; a withdrawal extends only the window's bound and term count). The close checks BOTH `storage_now = day start + rain - E - drainage - T` within the window's OWN MAPLE bound and `storage_now = initial + all rain - ... ` within the accumulated bound; a long history never loosens the day's bound. All ledger scalars/bounds must be finite and non-negative. A refusal leaves the accepted parent, cursor, expected parent and output unchanged; the retry works. One native storage query per audited close with or without an output.

## S3 — the CUDA branch of the SAME daily path (definitions only; not run on a GPU)
Backend-resident CUDA daily hydrology, withdrawals, audits and every-N output use the EXISTING qualified kernels (FSL resident step/recharge/state-check/storage, FT withdraw, the S0 evaporation law body, the G1 frame codec) through narrow branches in `floating_daily.py` and a plumbing helper `floating_daily_cuda.py` (no numerical body, CuPy only lazily). CPU/Numba arithmetic and order are unchanged (the 112 CPU tests still pass).
* **Residency and context.** A CUDA lineage keeps W/J/I on the device (the owner's arrays; J/I objects unchanged), the zero blocks on the device, the owner's resident depth/mask maps as the G1 `D`/mask (ONE device for W, D and the mask), the shared nominal edges and the active COUNT on the HOST (from the config edges and the bed's host mask pattern; no device scalar reduction). The cold witness scan and the first-use source-pair hash are HOST work against the host pool.
* **Pools.** DEVICE pool = `available_bytes_fn`/`reserve_bytes` (default: the real reading of the CURRENT device) and HOST pool = `host_available_bytes_fn`/`host_reserve_bytes` (default: the real host reader), each reserve counted once; a CPU lineage rejects the host-pool arguments. Every CUDA transaction gates the current device FIRST (before any reader, hash or array operation), checks metadata (exact `cupy.ndarray`, the column's device, FP64, C-contiguity, shape; no coercion, no upload), then admits ONE composed two-pool plan (`fdc.start_plan/day_plan/withdrawal_plan/audit_plan`, exactly the existing `operation_terms` + the S0 evaporation estimate) before any owned array/readback/hash.
* **Day.** ONE FSL step or recharge step per day with the staged post-cap E share; the surface-return check uses the step's packet scalar; no matrix/preferential call; P0/<=T/>T and the one-column capacity fallback are classified exactly as on the CPU (full native forcing, unchanged parent; the full storm is never claimed executed).
* **T.** The aggregate `(L, N)` request must already be device resident; actual/unmet/scale stay resident; one debit per accepted request. The CPU sparse aggregation stays CPU only (the caller owns an explicit upload).
* **Audit.** The final close runs the resident state check (32-byte packet) and the storage word (8 bytes) after the composed admission and before the mint; the CPU private value checks never receive a CuPy array; the same MAPLE bounds drive the daily-window and lifetime closures.
* **Every-N.** `FloatingMoistureOutput` is unchanged: its record is host metadata only; a due day streams W, D and the mask (all on the one device, edges host) through the G1 writer; not-due/off days add no traffic beyond the audited close.
Limits: no hardware run, the second-device branch is untestable under a one-UUID mask, N = 50003 plateau is defined for Root, no storm/Pond/Wind/Chastre/day-after-storm claim.

* The CUDA withdrawal request is validated as METADATA before any reader (`fsl._check_vec`: exact `cupy.ndarray`, the column's device, FP64, C-contiguity, `(L, N)`; no coercion/upload/array read) and only then admitted; the CPU order is unchanged.
* The device definitions now check the per-day clock as `accepted parent + 86400 s` (the model clock is cumulative: 172800 on the second day) over three complete days, with the cursor consumed once per completed day, and replace the former N = 50003 skip stub with executable moderate-fixture definitions (real native one-row bed, CUDA L = 3, default readers): warm day + ten released-parent days with synchronised/collected pool samples (plateau), peak payload with the trial references live against the composed `day_plan` plus the explicit 512 B x <=64-allocation pool rounding, and an N=2 due frame bit-exact against the accepted post-T W/D/mask with counted `to_host`/`to_device` pieces (the 32 B state check + 8 B storage word; bounded G1 chunks); implicit backend scalar syncs are not claimed as counted.

### S3 correction02 (test/doc wording only)
* The moderate N = 50003 device definition now distinguishes three quantities: the TRANSIENT peak (a real allocator hook installed with `cp.cuda.using_allocator`: every allocation goes through `pool.malloc(size)`, peak = max(`pool.used_bytes()` - baseline) at each allocation, actual rounding = sum of `ptr.mem.size - size`), admitted against the composed `day_plan` device bytes PLUS that very day's measured rounding; the LIVE-END footprint (pool used bytes right after the action with the trial references live; not the peak; asserted `<=` the peak); and the released-parent plateau (within one retained state plus the largest measured per-day rounding). The earlier "512 B x 64 allocations" allowance was an unverified declaration and is gone; nothing in the definition labels any bound as a proven peak before Root's hardware run.
* Replay semantics: notifying the SAME already-notified closed state is the established idempotent `repeat_same_state` (no I/O, asserted with an unchanged transfer list); the byte-verifying `verified_existing` path is exercised by `FloatingMoistureOutput.resume` at the accepted final boundary followed by `notify_day_closed` of that due day (G1 compares the sealed frame with the live W/D/mask).


## Wet interevent timestep exception approved 2026-11-13

The user authorized short hydrology and evaporation steps on wet interevent days, with transpiration and growth once at day end. Dry days keep one daily soil update. Wind, rainfall and their recession still exclude evaporation, transpiration and growth. A wet interevent day counts as one nominal day (86400 physical seconds), and optional every-N output follows final daily withdrawals and audited closure. This authorizes the numerical treatment; the coupled wet-day driver still needs implementation and CPU/GPU qualification. Earlier pending/refusal-only design notes are superseded by this decision.
