# Native Windowed CUDA physical checkpoint
The explicit CUDA checkpoint API now supports schema /8 for genuine native Windowed MAPLE beds and retains schema /7 for Dense beds. It saves the resident window and current hydraulic/sediment/soil state while referencing immutable external deep-store versions. The loader checks source, kernel, case, held-law and deep-store identities, validates the native soil partition and its packets on the host, places the actual native state on the device, then checks current geometry and physical closure before adoption. A pending journal must be published first.

The actual deep-store mapping-cache bound is part of the host memory model; it can greatly exceed the resident archive. Host and device budgets remain separate, with the existing declared host allowance and reserves. Floating transfers are counted and bounded; native MAPLE placement follows its own counted whole-array protocol. Deep files are neither copied nor rewritten.

Root verified 196 CPU tests and 25 GPU cases, including Dense regressions, genuine Windowed bitwise continuation and fresh-process restore, corruption/missing-store refusal, and a 50,003-cell/60-voxel/3-resident-voxel peak/release control. Independent native capacities of 300 and 5,000 voxels loaded at exact declared budgets. See `phase2_windowed_checkpoint_cuda_acceptance.json` for exact frozen source identities and limits.

A small resident voxel window does not imply an equally small TOTAL checkpoint: the hydraulic, sediment-phase, accounting and soil arrays remain separate. The moderate fixture's voxel window has exactly 3/60 of the full voxel array's entries, while its full physical checkpoint is larger than that voxel array because of the other fields. This qualification does not establish whole-Chastre or general coupled daily restart readiness.
