# Phase 2 H0 — water-free held law context (export / reconstruction)

`floating_held_context.py` (new; no existing production body edited). A pure LAW context: the true `NativeFloatingConfig` inputs, the ROOT prepared floating column (raw FC/SAT maps with their layouts, `D0`, active mask, area), the held matrix operator (incl. the texture-Ks vector) and an optional preferential operator re-prepared from an EXPLICIT `PreferentialSpec`. No water, J/I, state or owner; nothing is recomputed from a bed, a texture or the Saxton-Rawls provider. It is not physical acceptance, a source-bed proof, a checkpoint or file provenance.

APIs: `export_held_context(vertical, pref_spec=None, available_bytes_fn, reserve_bytes, verify=True)`, `HeldContextRecord.meta()/.arrays()` (strict JSON-compatible dict, floats as canonical `float.hex`; named sealed C-contiguous arrays), `record_from_parts(meta, arrays, max_bytes, ...)`, `reconstruct_held_context(record, ExpectedHeldIdentities, ...) -> HeldContext`, `estimate_held_context_memory`.
* Capture comes from the genuine `FloatingPondVertical.held_template()` + `vertical.config`; the ORIGINAL layer thicknesses (`config.layers.thickness_m`) are stored, never recovered from `diff(edges)`; `overrides` None vs `{}` vs real arrays are preserved; explicit and texture_ks modes; scalar/shared/cell FC/SAT layouts are carried through the public factories.
* The preferential operator keeps only derived maps: the spec's raw `a3`, max rate (scalar/cell, `inf` allowed where the physics allows), receiving weights and species contributions must be supplied; export REQUIRES the exact operator `sha256` from the public preparation (never reverse-engineered). A `verify=True` export performs a full dry reconstruction.
* Parse: exact keys/schema/types/dtype/shape/C-contiguity BEFORE any copy or reader call; byte cap; admission before the sealed copies; a private integrity digest (all metadata and array bytes) re-verified before every use. Reconstruct: public factories only (`native_floating_config`, `prepare_floating_column`, `prepare_floating_matrix`, `prepare_floating_preferential`), every sha compared with the caller's `ExpectedHeldIdentities`; the minted `HeldContext` is uncopyable (tight window, no callbacks). CUDA is refused by a typed error before any coercion/read.
* Memory model (declared, modelled host bytes): record arrays `O(L N + (S+1) N + L K + overrides)` + the existing retained component estimates + the largest preparation scratch + 64 KiB; real default host reader when none is given, strict non-Boolean reserve, zero/need-1/exact for parse and reconstruct.

Future use: `FloatingPondVertical.from_held_context(ctx, ...)` and the general file codec take a `HeldContext` (config, column, matrix operator, preferential, `D0`, Ks, mask, generation, witness) instead of a `NativeFloatingSoil` and restore the current payload from their own verified file; they own source/file verification and the full native/Pond audits. Limits: CPU only; no codec, no daily profile, no physical acceptance; a minted context guarantees only that the public factories reproduced the expected identities from the record values.

## Correction01
* **Metadata first.** `_check_meta(meta, n_arrays)` validates the record metadata in place with NO JSON round trip, deep copy or allocation proportional to the input: closed key sets at every level (top, scalars, layouts, `layouts.all` = the genuine FSL layout names `theta_residual/theta_field_capacity/theta_saturation/interface` with kinds scalar/shared/cell, identities, facts, pref), exact types, bounded strings (hex <= 64 chars, 64-hex digests), override names from the provider's own `OVERRIDES` set, and every declared count bounded by the number of arrays actually supplied. `_analytic(meta)` then computes the array COUNT and BYTES from the declared inputs by arithmetic alone and refuses an unsupported resource (count mismatch or above `max_bytes`) before any name, shape or copy is built; the same in-place validation precedes `_verify` and `meta()`. No species/layer limit was introduced: the cap is analytic from the declared inputs and `max_bytes`.
* **Required scalars.** Every NativeConfig scalar is a canonical finite `float.hex` (None / `inf` / NaN / non-canonical / non-string are typed refusals at the metadata, before any copy); only the two mode-specific conductivities may be None (exactly one per mode); `inf` is accepted only for the scalar maximum intake rate of the preferential operator. Physical bounds stay with the public factories (a well-formed but out-of-range value is refused there).
* **Export.** `_snapshot` builds metadata and REFERENCES only; the `(S, L)` species-weights block, every sealed copy and the verification reconstruction are created only after the composed admission (the "nothing was allocated" message is true). `PreferentialSpec` documents its construction working set and `PreferentialSpec.admitted(...)` is the same construction behind the real host reader.

## Correction02 (admitted `PreferentialSpec` constructor model)
`PreferentialSpec.admitted(...)` previously admitted `raw payload + 64 KiB`; the reproduced S1000 L3 N3 case (raw 48 048 B, need 113 584 B) really peaked at 307 621 B because each of the `2S + 2` arrays also costs Python/NumPy objects (the sealed copy's header, its slots in the transient and final tuples, the sealing generator). The declared need is now `PreferentialSpec.construction_need(...)` = raw ndarray payload + `SPEC_ARRAY_OVERHEAD_BYTES` (512 B, a declared bound calibrated from the measured ~120-140 B per array at S = 65/1000 with a ~4x margin) per ndarray + 64 KiB, computed from existing array metadata only (no copy, no list/tuple of parts); `species_*` must be a bounded tuple/list (an iterator is refused before it is consumed); the strict reserve is counted once. Direct constructor semantics stay documented as caller-owned parameter construction.
