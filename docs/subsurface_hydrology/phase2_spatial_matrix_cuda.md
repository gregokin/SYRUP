## What changed
* `matrix_infiltration_cuda.py` now renders its kernel text from shared pieces through the pure, fail-closed `render_source`: the Newton helpers (`log1pmx`, `ga_increment`, `_NEWTON`) and the kernel body (`_BODY`) are written ONCE; the designated read/store sites are explicit `@@TOKEN@@` placeholders with declared occurrence counts. The COMMON rendering is byte-identical to the previous kernel text (sha256 `b58178df…`, checked at import and by tests); common options, name, launch ABI and arithmetic are unchanged.
* New `spatial_matrix_infiltration_cuda.py` renders the SAME Newton text and body with spatial readers (`fc = theta_fc dz`, `sat = theta_sat dz`, `sat + coef sat`, strided K/psi/g), a `__device__` head and a reduction tail; compiled with the existing `--fmad=false --prec-div=true --prec-sqrt=true --ftz=false`.
* `spatial_matrix_infiltration.py`: the same public functions now accept a CUDA owner (`SpatialSoilColumn(backend="cuda")`): exact CuPy float64 C-contiguous arrays of the owner's device (current device checked first, nothing transferred), device quota/reserve/reader plus the separate `host_memory_budget_bytes` / `host_reserve_bytes` / `host_available_bytes_fn` (refused for CPU owners). Physics, CPU interfaces, canonical identity recipe, numerics and CPU quotas are unchanged. New explicit history metadata `namespace`/`device_id` default to the CPU values; no CPU history is migrated or rebound.

## Fused bounded reduction
Per lane the shared body stores its fifteen contributions straight into static shared rows with literal offsets (rows 0–13 the sums of the common packet, row 14 the maximum Newton iteration count; padded/inactive lanes 0), the flag word is OR-ed and invalid cells counted; one fixed block tree (`15·8·128 + 8·128 + 4·128` B static shared), `15·nb` block partials, one `atomicOr` and one `atomicAdd` per block into the 17-word `uint64` raw packet, then a one-block finalize (`15·8·256` B). ONE `to_host` of 136 B; the host rebuilds the unchanged 17-float packet (lowest set bit of the OR = minimum per-cell lowest bit, or `NO_FLAG`; flagged-cell count counts each invalid cell once, inactive water included) for `matrix_infiltration._resolve_core` (finite-before-bound, `n_terms`, max operand scale, area once). No dense `16 N` rows, no CuPy/CUB reduction or workspace, no L-sized or per-thread contribution arrays, no host mirror, no per-call H2D. Every lane reaches every barrier (the guard is a `return` only inside the `__device__` function). Sums are fixed-tree ordered (roundoff-level different from NumPy/Numba); the closure bound still applies. Register/local/occupancy behaviour is NOT assumed: Root measures actual resources and timings.

## Memory model (payload; not a reservation; NVRTC/context/pool rounding excluded)
step device `(4N + LN)8 + 15·8·nb + 136` (+ reserve); host `272 + 65 536` (raw 136 B + rebuilt 136 B packets + allowance, + host reserve). history device `2N·8 + 8`, host allowance. prepare device `3N·8 + 8` (upper bound; a scalar keeps 8 B), host `min(N, 16 384)·8 + 8 + 65 536` (the bounded identity-hash staging buffer). Cold validation uses one tiny kernel and an 8-byte diagnostic. Admission (device and host quota, reading, reserve) precedes every allocation, conversion, copy, compile and launch.

## Limits
Fixed explicit geometry/properties; no policy choice; no preferential CUDA (S2-B2.d), native B3, moving-bed or source-guard adoption. Kernel compile/load happens at preparation (function cache per device only). Device libm may differ from NumPy by an ulp (declared rtol 2e-12 / atol 1e-14; bitwise where no logarithm is evaluated); Newton iteration counts are not universally equalised across libms.

## Review01 (2026-11-12): open inherited split-recombination roundoff defect — NOT corrected, NOT qualified
Root's GPU run (238 passed, 3 failed) exposed two valid-input history-sequence cases that the STRICT common contract refuses at their second step (`dt = 3600 s`) with bit 17 (`step produced negative soil, pool or history`, one cell): `(L=3, N=128, all_shared)` cell 103, pool `0.04838095732241791`, pool-out `-6.938893903907228e-18`; `(L=5, N=257, scalar_thetas)` cell 248, pool `0.029264621197886812`, pool-out `-3.469446951953614e-18`. The new spatial NumPy path, the new spatial CUDA path and the accepted common CUDA operator all refuse the same cell at identical state/law/forcing, and the author's CPU run reproduces both exactly (`tests/phase2_spatial_matrix_cuda`). It is therefore an INHERITED numerical defect of the Phase 1 law, not a spatial reader or reduction mismatch, and it is not an environmental limit: these valid inputs do NOT integrate under the current source.

**Mechanism (cell 103).** The cell has an in-interval onset (`pre = 0.0060843600909219996`, unponded phase) and then a ponded phase limited by the pool: `post = pool_left = fl(pool - pre) = 0.04229659723149591`. The recombination `intake = fl(pre + post) = 0.048380957322417914` is one ulp ABOVE the pool `0.04838095732241791` (`fl(y + fl(x - y)) != x`), so `pool_out = pool - intake < 0` and `rejected = bounded - intake = -6.938893903907228e-18` also goes negative. Cell 248 is the same pattern (`pre = 0.011365670293866334`, `post = 0.01789895090402048`, `pre + post = 0.029264621197886816 > pool`).

**Locations (current sources).** Common NumPy `matrix_infiltration.py` `_reference_step_body`: `pool_left = pool_in - pre` / `room_left = room - pre`, `post = min(c2, pool_left, room_left)`, `adv = post / g_map`, `intake = pre + post`, `rejected = bounded - intake`, `pool_out = pool_in - intake`, `cum_out = cumulative_in + intake` (lines ≈1049–1066); Numba `matrix_infiltration_numba.py` `step_core` (lines ≈317–336, same statements); CUDA `matrix_infiltration_cuda.py` `_BODY` (lines ≈200–216, same statements; the spatial CUDA module renders this very body). The same recombination applies to the saturation room (`room_left = room - pre`, `w0 + intake`), where the existing capacity tolerance absorbs it; only the pool, with no tolerance and an `output >= 0` check (bit 17), refuses.

**Proposed bounded numerical correction (a SEPARATE independent task; Root decides and reviews it before whole-Phase-2 acceptance).** Bound the COMBINED actual intake rather than the two parts: `intake = min(fl(pre + post), pool)` (and, symmetrically, `min(..., room)`), then derive the consistent actuals from it — `post_actual = max(fl(intake - pre), 0)`, `adv = post_actual / g` (g > 0), rows `pre`/`post`/`rejected`, `pool_out = pool - intake`, `cum_out = cumulative_in + intake` — so that pool, soil, history and ledger all see ONE intake and the physical identities hold by construction. Requirements for that task: apply identically to the common NumPy/Numba/CUDA bodies and, through the shared body, to the spatial paths; no epsilon, no erasing or clipping of a negative result after the fact, no source-guard loosening, no change of formulas, defaults, flags or bounds; add the two cases above (cell, pool and values recorded in `tests/phase2_spatial_matrix_cuda/conftest.py::STRICT_REFUSALS`) as regressions on every backend; verify Root's frozen 32-scenario/224-column controls and the 160-case common GPU baseline for unintended change (bitwise where the new bound is inactive).

**What this task proves and does not prove.** `tests/phase2_spatial_matrix_cuda` now distinguishes an equivalent success from a PAIRED strict refusal (same typed bit and flagged-cell count on the CPU spatial path, inputs/state/history/pool unchanged, the occurrence ends without an adopted continuation; a one-sided refusal fails) and defines explicit regressions of the two original refusals. That proves FAILURE COMPATIBILITY ONLY. It does not show that these inputs integrate successfully, it does not qualify the CUDA matrix for all valid inputs, and no production file, bound, tolerance or default was changed.
