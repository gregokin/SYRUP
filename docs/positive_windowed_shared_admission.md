# Explicit positive windowed CPU water admission

This opt-in lane uses `PositiveWindowedWaterBridgeLimits` and
`complete_positive_windowed_event`. It supports the closed C16 (4×4), V6, W3,
K1, NumPy float64, full-v1 profile with Native M2/G4/J320, tracked availability,
constant-depth water updates and enabled Native avalanche. Its Native source,
provider/order/image and all physical validators remain mandatory. A Source
identity string is metadata; it grants no runtime or provider authority.

The wrapper calls original `complete_event` once and returns that exact
`DryHandoff` plus immutable admission counters. It requires an explicit
original control/policy; external continuation, checkpoints and custom
hydraulics/callbacks are excluded. The original 4096 report declaration,
10000 steps, ten retries, 64 transport substeps, 256 commit records and 100
rejection records remain. Rainfall, recession, quiet criteria, routing trigger,
forcing/solver clocks, sediment and water budgets, dry reset and terminal
settlement are unchanged. A duration, resource or allocation failure remains
incomplete. The future MASY adapter must retain the full real routing and bed
owners; this lane does not implement that adapter or a restart codec.

The only public Native water-demand option added is `max_gather_columns=4`,
for this exact new family. The legacy/default/D2 family retains its previous
batch rule and every old function body. The shared validator still inspects
all seven bed fields, physical inventories, reconciliation/availability,
Original and the complete published partition. No new sediment is injected.

A private synchronous owner binds the original context, process birth, thread,
storm and immutable control fields. Original complete-event's actual
`replace(control, force_final_commit=False)` is admitted once by exact scalar
projection and then actual object identity. The other control fields and
storm identity remain exact. Readonly initialization/metadata does not permit
a physical transfer/publication. All new-family physical calls independently
require the active owner; escaping failure poisons it and closes only its
control lease, without rollback or deleting any versions.

Before each fixed metadata/action/publication gate the lane reads current
mapped address space using birth-bookended bounded `/proc/self/stat` and
`statm` reads. Actual soft and hard AS must both equal the original 4GiB.
Future complete Native requests/policy prefixes, public Source outputs,
planner/report/log containers, storage/partial versions, helper/error/reader
owners, and the original positive reserve are added to this current extent.
This is a prospective refusal predicate, not a measured peak, heap theorem,
provider scratch certificate or guarantee that the next allocation fits.
Root must qualify the selected Linux proc/ABI/CPU provider/runtime semantics
and actual Source/currentness before execution. Unknown reads/domains refuse;
no setter, zero fallback, GC or presumed release is used.

Work/read/version debits are monotone and made before the relevant action.
The Source tables distinguish one forward attempt from cumulative retries;
previous/retained errors remain in current mappings. Every writer rescans the
owned run/store including old, orphan and partial files and forecasts complete
caller plus Native writes and temporary/final entries under unchanged 64MiB
store, 128MiB run and 4096-entry limits. Native and Root file/FD/CPU/wall/output
limits remain authoritative. No version is removed or deduplicated as credit.

Physical commits first admit publication plus both outer-metadata and future
wet-stage prefixes. They publish the genuine pending journal and fully validate
the published result. On its actual pending-free state they issue/check the
real Native outer `_ClosedWaterRequest`, add the unchanged exact requirements,
and call the genuine wet stage, which independently issues its own request.
The original stage's water callback/box/Original/error/output costs remain.
Publication, outer request and physical stage use the same actual solver time;
storage-only publication retains its distinct existing storage reference time.

The Source-only metadata tests challenge limits, parsing, stale/equal-cloned
controls, ownership, atomic cumulative refusal and exception preservation.
They establish no physical success. Root separately qualifies the complete
positive-water result against the unchanged Dense control, including all
fields, budgets, availability, routing and retained deep versions. All actual
operands and outcomes were unavailable to the Source author/reviewer.

The owned run/store domain is quiescent and has one writer. Parent components,
symlink/nonregular inventory entries and unknown bounds refuse. The inventory
is not a hostile concurrent-directory-swap transaction: Root must keep the
owned paths unchanged between scan and write. Selected proc read completeness,
52-field stat and statm/page semantics remain Root platform prerequisites. The
available-memory check compares the positive future reservation; the separate
AS check adds actual current mappings. Neither is a peak/fit assertion.

New-family literal admission refusals poison the active owner immediately.
Original shared/helper refusals propagate in this fixed step-publication lane:
its generic ValueError handler rethrows, and only the distinct hydraulic/
transport rejection classes retry. Escaping errors poison/close the fixed
entry. This states no guarantee for arbitrary outside catchers. Original
Native hydraulic retry decisions are unchanged.

## Positive entry forced commit (Source only, unqualified)

`commit_positive_windowed_entry` performs one genuine `commit_bed(...,
force=True)` under its own private positive owner, separate from
`complete_positive_windowed_event`, whose body is unchanged. It requires the
explicit original control and held routing source, then runs the literal
metadata, owned gate, validator and that one commit. It returns the exact
Native `BedCommit` plus this owner's immutable `PositiveWaterAdmissionSummary`;
the result's state, graph and routing-source identities are checked, not
rebuilt. Escaping errors keep their identity, poison and close the owner and
clear only its own lease. An existing owner or scope refuses re-entry and is
never replaced or cleared.

The outer holding bank is a logical Source law derived from the entry's own
call/frame/return/error graph. It retains the complete pre-gate metadata,
prices one complete Native metadata prefix (never sparse proof alone), and
relies on the complete unchanged `commit_bed` tail and its inner gates. It
takes no spare-capacity, GC or release credit. Two entry-only seam
statements add it to the existing gate/bootstrap predicates only while the
entry scope is installed; otherwise they are absent. The existing helper
bank, its limits and all other limits are unchanged.

Each call's summary is per owner. A future MASY adapter must aggregate entry
and event summaries before adopting the event, under the original selected
cumulative ceilings. Store/run/entry inventory caps persist through both,
with no credit between them. Native physics, routing threshold, commit,
recession and dry reset are unmodified.

This API is Source-only and unqualified until Root's actual checks. The
qualified profile above covers only `complete_positive_windowed_event`, not
this entry. The focused tests use explicit synthetic delegates. They
establish no physical success and fabricate no Native certificate. Root
separately authors and runs the genuine entry-vs-Dense oracle under the
original 4GiB controls. No performance, heap, fit, restart, windowed-GPU or
combined wind/water claim is made.
