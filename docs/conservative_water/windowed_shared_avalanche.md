# Opt-in K1 shared windowed water with Native avalanching

This is a Source implementation of a limited new interface family. It is not
physical qualification. Root must separately qualify the exact composed Source,
provider/E1/order state, compiled objects, runtime, Native D1 fixture policies and
actual targeted executions. At handoff there is no accepted D1 physical result.
Existing ordinary `BedState` / `BedContext`, defaults and checkpoint wire remain
unchanged after the documented exact inverse.

`WindowedSharedBedState` adds the REQUIRED seventh field
`reconciliation_baseline`. Pass the genuine Native reference, including a valid
`None` when Native rules permit it. Every water replacement, actual pickup and
deposit, commit, storage rebind and terminal splice retains or forwards that
field; the accepted Native commit's returned baseline is authoritative.
`WindowedAvalancheContext` inherits the ordinary context and requires eight
additional keyword-only Native policy / Source-metadata / bridge declarations.
Its Source tag is never a runtime or provider certificate.

The first eligible profile is NumPy, K1, square unmasked cells, fixed capacity,
a single full-v1 deep chunk with Native prefix packets, tracked water and
availability, BOTH real Native process channels, enabled Native avalanching,
`constant_depth`, step publication, no exchange history or overlay. Hydraulic
implementation must be `array`, root solver `bisection`, phase storage `dense`
and resolved transport `array` (existing dense characteristic or upwind).
Unsupported compiled/CSR/Newton/GPU families refuse before new event arrays or
transport. No solver law, tolerance, timestep, availability, water completion or
soil-reset policy is changed. The new family has no SAVE/LAYOUT/LOAD codec and
refuses those paths before arrays or I/O. K6 wet, MASY shared carrier, restart,
GPU, coupled/production/large-domain claims remain separate.

The new admission first checks finite exact Native holder / primitive backing
metadata, the actual pending-capable BedExchange plan B, held Native provider and
E1/order prerequisites, current/prior external root occurrences and explicit
bridge limits. It reserves the complete future wet Native policy N plus all
external owners; it cannot issue a published-only Native request from pending
state. Actual Native publication happens once if required, then the unchanged
wet stager issues a FRESH real request on that published column. Its original
four-field return supplies result, availability, water and depth update; the
adapter neither invents a `ran` flag nor republishes the private Native box.
The actual old routing tail runs once, with retained graph/source and the actual
Native rerouting threshold. Publication is storage authority only; it does not
by itself accept a physical boundary.

`WindowedWaterBridgeLimits` contains finite logical declarations under the
original 4 GiB AS, CPU120/wall180, 64 MiB store and 128 MiB run controls. The
bridge adds native B/N, every original/current/prior backing occurrence,
Source-derived visible array/header requests with explicit loop multiplicities,
metadata/error/namespace roles, mappings, reads, work and all old/new/orphan
version plus partial-write bytes. No alias, GC or hardlink credit is used.
Provider-private/Python/OS overhead remains a positive reserve and genuine Root
prerequisite. This is not a total heap/RSS/time/fit proof. Actual headroom and
Native admission may still refuse; no cap is increased to make a fixture pass.

One commit can create at most two Native COW versions (input prepublication and
accepted output publication). A finite event reserves accepted steps A, retries
R+1, at most M=A+1 commits and A+2M+1 storage opportunities, including terminal
work. No old version, orphan or partial is collected. Errors propagate with the
last accepted caller state and durable old versions intact; an unadopted new
version does not become accepted authority.

Terminal completion uses the ORIGINAL continuous quiet interval, exact current
StormState clock, actual Native mobile settlement, original wet/soil budgets and
external dry-reset policy. Both wet and dry beds must be the exact new family
with identical non-water references before publication. The genuine published
column AND returned reconciliation baseline are jointly rebound into the dry
wrapper. Each output retains its own water object. No soil/water is dropped at
an adapter boundary and no fresh bed or DEM is reconstructed.

The new tests are explicitly synthetic interfaces: an independently initialized
Dense/Native positive moving-avalanche oracle, real water demand/step, fresh
publication and baseline ownership, unsupported profile/codec/time/dtype/channel
refusals, and a zero-domain two-step terminal transaction under the ORIGINAL
60-second quiet criterion. Dense materialization exists only in the independent
small test oracle. All tests are unexecuted by the Source author; successful
Native D1/current-provider qualification and actual collection/check are required
before any acceptance claim.

The initial opt-in storage envelope is K1 and at most four cells: its genuine
BedExchangeLimits gather allowance must cover all cells, with two exchange
operations. The synthetic two-cell controls declare G2; Native hard maxima stay
unchanged. Direct with_water/apply_bed_demand calls also reserve authentic
primitive input roots before Native value validation. Optional arbitrary
hydraulic diagnostic records, compiled/CSR/Newton solvers and other backends
remain outside this profile.

The synthetic Dense comparison uses the exact recursive diagnostic helper: dictionaries, dataclasses and sequences retain exact types, all keys/fields/elements are visited, and every leaf keeps the original array dtype/shape/bytes and float-hex checks. No physical assertion or numerical bound is omitted or relaxed.
